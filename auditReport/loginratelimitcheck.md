## 1. 基本信息

- 项目：spring-boot-file-security-lab
- 审计模块：用户登录接口
- 接口：POST /api/user/login
- 测试工具：Postman、IntelliJ IDEA、本地 Spring Boot 测试环境
- 审计日期：2026/10/25
- 风险类型：Brute Force（暴力破解）、登录接口缺少限流

## 2. 审计目标

检查登录接口是否限制连续失败登录和短时间内的高频请求，防止攻击者通过大量密码尝试获取账户访问权限。

## 4. 回归验证

- 正常登录功能可用。
- 错误密码不能获取Token。
- 达到限制后不能继续尝试登录。
- 限流期结束后可以恢复登录。
- Token验证及文件权限接口不受意外影响。

## 6.风险分析与修复局限

### 6.1 当前实现的局限

1. **进程内存存储：** 登录失败记录保存在 ConcurrentHashMap 中，应用重启后记录会清空；多实例部署时，各实例之间也不会共享限流状态。
2. **缺少独立的 IP 级限流：** 当前按用户名与 IP 组合统计失败次数，攻击者更换用户名时可以产生新的统计记录。
3. **客户端 IP 信任边界：** 当前直接使用 `HttpServletRequest.getRemoteAddr()`，不直接信任客户端提供的 `X-Forwarded-For` 请求头。未来部署在反向代理后时，需要正确配置可信代理及客户端 IP 解析策略。
4. **分布式部署限制：** 生产环境可以考虑使用 Redis 等共享存储实现限流，并结合网关层请求速率限制、异常登录监控及告警。

### 6. 2当前审计结论

本次实现已针对连续错误登录增加临时限流，并对正常登录、限流期间登录及限流期结束后的恢复行为进行了测试。

本结论仅适用于已测试的代码版本和本地测试环境，不代表已完全消除所有暴力破解风险。对于用户名轮换、来源 IP 变化、多实例部署及分布式攻击等场景，仍需进一步验证和完善。
