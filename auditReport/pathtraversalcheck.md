# 路径穿越风险审计与修复记录

## 1. 基本信息

- 项目：spring-boot-file-security-lab
- 审计模块：文件上传、下载、删除
- 审计日期：2026-10-23
- 测试工具：Postman、IntelliJ IDEA、本地 Spring Boot 测试环境
- 风险类型：Path Traversal（路径穿越）

## 2. 审计目标

检查文件相关接口是否可能因不安全的路径拼接、原始文件名处理或不可信的数据库路径，导致应用读写上传目录之外的文件。

## 3. 检查范围

- [ ] 文件上传：检查 originalFilename 是否参与物理路径拼接。
- [ ] 文件下载：检查数据库文件路径是否经过目录约束。
- [ ] 文件删除：检查删除目标是否限制在上传目录内。
- [ ] 用户权限：检查文件所有权验证。
- [ ] 异常处理：检查是否泄露服务器物理路径或堆栈信息。

## 5. 修复计划

- [ ] 上传时使用服务器端生成的存储文件名。
- [ ] 将文件存储路径限制在配置的上传根目录内。
- [ ] 下载和删除统一使用安全路径解析逻辑。
- [ ] 检查规范化路径，并拒绝越出上传目录的目标。
- [ ] 检查符号链接与文件系统权限。
- [ ] 保留现有身份认证及文件所有权验证。
- [ ] 对路径错误返回通用错误信息。

## 6. 验证与回归

- [ ] 正常上传、下载、删除全部回归测试通过。
- [ ] 路径穿越测试无法读取上传目录外的测试文件。
- [ ] 路径穿越测试无法删除上传目录外的测试文件。
- [ ] 其他用户的文件仍受到所有权检查保护。
- [ ] 错误响应未泄露敏感服务器信息。
- [ ] 保存 Postman 测试证据。
- [ ] 检查 Git 变更并提交修复。

## 7. 学习总结

本次审计关注用户可控路径与文件系统操作之间的安全边界。

修复原则：
1. 不直接使用客户端原始文件名作为物理存储路径。
2. 使用服务器生成的文件名和固定上传根目录。
3. 对实际文件路径执行目录约束检查。
4. 将路径安全检查与身份认证、文件所有权校验分别验证。
